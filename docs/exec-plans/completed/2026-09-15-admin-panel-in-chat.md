# admin-panel-in-chat: /admin в чате открывает админку этого чата

## Контекст
- `/admin` работал только в личке (список чатов), в группах команду перехватывал
  `cmd_admin_reload` — перечитывал только кэш админов и отвечал «OK».
- Жалобы на старое название чата в панели: `get_chat_title` читает многослойный
  кэш (память → база → API) без инвалидации при переименовании.

## План изменений
1. [x] `routers/admin_panel.py` — `refresh_chat_title()`: свежий title из API,
       апсерт в базу и обновление `_chat_titles`.
2. [x] Групповой `/admin`: одна выборка `get_chat_administrators` → проверка админа
       (не-админу — эфемерный отказ), перечитывание кэша админов, рефреш title,
       эфемерка с url-кнопкой deep-link `t.me/<bot>?start=admin_<chat_id>`, удаление команды.
3. [x] `CommandStart`-хендлер `admin_<chat_id>` в личке: проверка админа по API,
       рефреш title, сразу `chat_menu_kb(chat_id)`.
4. [x] `tests/routers/test_admin_panel.py` — обновлён тест группового `/admin`,
       добавлены: отказ не-админу в чате, deep-link открывает меню, отказ по deep-link.
5. [x] Проверка: ruff, pyright, pytest (880 passed).

## Риски и открытые вопросы
- Панель сознательно открывается в личке (один клик по кнопке), а не постится
  в группу: колбэки панели не переписаны под эфемерные сообщения, а публичная
  панель в чате — палево.
- `start_router` ловит только `/start` без аргументов — конфликтов с deep-link нет.

## Верификация
- `uv run pytest tests/routers/test_admin_panel.py -q` — 49 passed.
- Вживую: `/admin` в чате под админом → ephemeral-кнопка → в личке меню этого чата;
  переименовать чат → `/admin` → кнопка с новым названием.
