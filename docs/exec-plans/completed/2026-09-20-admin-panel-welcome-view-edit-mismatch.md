# admin-welcome-view-edit: единый вид велком-текста в просмотре и редактировании

## Контекст
- Жалоба: в `/admin` → Welcome при просмотре сообщение одно, при редактировании — другое.
- Корень в `routers/admin_panel.py`: просмотр и редактирование показывали сохранённый текст по-разному:
  - Просмотр (`_format_welcome_settings`): `_preview_text(msg, 450)` + `html.escape` → текст обрезан, HTML-теги сырьём, хвост с капчей-строкой `$$COLOR$$` не виден.
  - Редактирование (`_build_welcome_edit_prompt`): `_preview_text(msg, 1200)` без экранирования, отправка без parse_mode → дефолт бота HTML → полный отрендеренный текст.
- Доп. требования (из обсуждения):
  - Предпросмотр должен отражать режим капчи: при `$$COLOR$$` в тексте кнопка «я не бот» НЕ показывается — вместо неё эмодзи-капча; при выключенном фичефлаге `captcha` кнопки нет вообще.
  - Подсказка `{name}` врала: код подставляет `$$USER$$` (welcome.py:407); `$$COLOR$$` нигде не упоминался.
- Ветки капчи, влияющие на велком (`new_chat_member`, welcome.py:402-453): flag off → нет клавиатуры, `$$COLOR$$` остаётся сырьём; flag on без `$$COLOR$$` → одна кнопка (welcome_button, дефолт «I'm not bot»); flag on + `$$COLOR$$` → эмодзи-капча v2 (6 квадратов), текст кнопки не используется. Selfmod on → велком не отправляется вовсе. `join_request_captcha` — вебапп-капча для чатов с заявками, к велкому не относится.

## План изменений
1. [x] `routers/admin_panel.py` — `_preview_html` (единый лимит 3500, зачистка полуобрезанного тега при truncation), просмотр без `html.escape` для текста сообщения (рендер как у нового участника), экранирование осталось для `title` и текста кнопки.
2. [x] `routers/admin_panel.py` — `_build_welcome_edit_prompt`: тот же лимит/та же обработка «Current:», подсказка `$$USER$$` + `$$COLOR$$` вместо `{name}`.
3. [x] `_format_welcome_settings` — строка «Button:» по режиму капчи:
   - captcha off → `Button: not shown (captcha disabled)` + предупреждение, если в тексте `$$COLOR$$` (плейсхолдер не подставится);
   - captcha on + `$$COLOR$$` → `Button: emoji captcha (colored squares) — welcome button text is not used`;
   - captcha on без `$$COLOR$$` → `Button: <текст>`;
   - selfmod on → приписка, что велком вообще не отправляется.
4. [x] Тесты `tests/routers/test_admin_panel.py`: `TestWelcomeSettingsDisplay` (9 кейсов: рендер HTML, лимит, режимы кнопки, selfmod, безопасная обрезка) и `TestWelcomeEditPrompt` (4 кейса: плейсхолдеры, без сервисов, кнопка, совпадение лимита с просмотром); обновлён интеграционный `test_cb_show_welcome_settings`.

## Риски и открытые вопросы
- Риск: сохранённый руками в БД невалидный HTML может уронить `edit_text` с parse_mode=HTML; вызовы обёрнуты в `suppress(TelegramBadRequest)` — деградация мягкая (панель не обновится). Источник текста — `message.html_text`, он валиден.
- Решение по семантике: и просмотр, и «Current:» показывают ОТРЕНДЕРЕННЫЙ текст; исходник с тегами админ не видит нигде.
- Не тронуто: при копипасте отрендеренного «Current:» форматирование теряется (админ пересылает плоский текст) — отдельная история, не входила в скоуп.
